# Completion Report Template

## Completion Report

### Specification
The locked goal, briefly.

### Delivered
The major behaviours implemented.

### Evidence
Criterion → evidence. For E2E: plan/scenario id, surface and tool, SHA, and the key confirmation (element text and handover screenshot path, API status and excerpt, CLI exit code and excerpt).

### Swarm execution
Streams, tiers and notable routing decisions.

### Integration findings
Important cross-stream defects and how later rounds resolved them.

### Residual risks
What genuinely remains: skipped environmental tests, acknowledged evidence substitutions, out-of-scope pre-existing defects.

### Change set
Final branch, PR or commits.

### Proposed process changes
For human review, never applied by the orchestrator. One item per recurring defect class or lesson, or "none":

- **Class / lesson:** what went wrong or worked, in one line.
- **Evidence:** defect IDs, rounds or incidents from this run.
- **Proposed amendment:** the skill file and section, and the change in a sentence.

Never claim success while relying on an unresolved assumption.
