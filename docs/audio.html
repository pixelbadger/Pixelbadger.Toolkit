Overview

The audio topic records audio to an Ogg Opus file and edits existing Ogg Opus files. record captures live audio from a microphone (through ffmpeg) or reads a WAV file, and writes a new .opus file. insert and overwrite put new audio into an existing file at a given time, editing the file in place.

Edits do not decode and re-encode the whole file. Existing audio packets are copied byte for byte, and only the new audio is encoded. Edits are described in How edits work.

$ pbtk audio <action> [options]

Requirements

libopus is required for every action. The toolkit loads the system library at run time and does not bundle it. If it cannot be found, the command prints the install guidance and exits with code 1.

PlatformInstall libopus
Debian / Ubuntuapt install libopus0
macOSbrew install opus
WindowsPut opus.dll on PATH

ffmpeg is needed only for live capture, that is, when --from-wav is not given. --from-wav works without ffmpeg. If ffmpeg is missing for a capture, the command exits with code 1 and suggests installing it (apt install ffmpeg or brew install ffmpeg) or using --from-wav.

--capture-format is an ffmpeg input format name, and --device is the device name ffmpeg uses for that format. Use them to choose a different microphone or to capture from another source.

Live capture needs ffmpeg and an audio input device. For scripted or headless use, give --from-wav instead.

record

Creates a new Ogg Opus file at --out-file. The audio comes from a live capture, or from a WAV file when --from-wav is given. An existing file at --out-file is overwritten.

Without --duration, a live capture runs until you press Enter or Ctrl+C. The command prints Recording... press Enter or Ctrl+C to stop first, then finishes the file cleanly and exits with code 0. With --duration, the capture stops after that length. --from-wav with --duration truncates the WAV to that length.

Stopping a capture

CommandEnterCtrl+C
Live capture without --durationStops the capture. The take is saved and the exit code is 0.Stops the capture. The take is saved and the exit code is 0.
Live capture with --duration, or --from-wavIgnored. The capture runs for the full duration.Aborts. Nothing is written (no output file for record, the original file untouched for insert and overwrite, no temporary file left behind). Prints Cancelled; no changes were written and exits with code 130.

When a take is being saved after a stop, further Ctrl+C presses are ignored, so pressing it twice does not lose the take. Over MCP, cancelling or timing out a call aborts it by the same rule, because MCP calls always carry --duration or --from-wav.

Memory: a recording is held in memory until it is saved, at about 350 MB per hour of mono audio (twice that for stereo). Very long recordings need that much free memory. Peak memory stays below twice the raw audio plus 200 MB: a 30 minute mono recording peaks at about 270 MB with --duration 1800s and about 390 MB when stopped with Ctrl+C.
$ pbtk audio record --out-file ./memo.opus --duration 10s
$ pbtk audio record --out-file ./memo.opus --from-wav ./take.wav
$ pbtk audio record --out-file ./memo.opus --channels 2 --bitrate 96000 --device "audio=Microphone" --capture-format dshow --duration 30s

Output

On success the command exits with code 0 and prints the path and the duration. For the first example above:

Recorded './memo.opus': 10.000s

The duration is the exact length of the audio, counted in samples at 48 kHz. Tools that read the Ogg container, such as ffprobe, report a duration that is 6.5 ms longer, because they include the encoder's pre-skip.

If a capture ends before the requested --duration, because the device or source ended, the command prints a warning and continues with what was captured, exiting with code 0. Here the source (an ffmpeg sine generator limited to 1 s) ends after 1 s of a requested 3 s:

$ pbtk audio record --out-file ./short.opus --capture-format lavfi --device "sine=frequency=440:duration=1" --duration 3s
Warning: capture ended after 1.000s, before the requested 3.000s
Recorded './short.opus': 1.000s

If the capture source fails part-way (for example ffmpeg is killed or the device disappears) after audio was captured, and the failure is not your Ctrl+C, the command prints a warning with ffmpeg's error and continues with what was captured, in both live and --duration captures. Here ffmpeg was killed 2.8 s into a 10 s recording:

Warning: capture failed after 2.773s: ffmpeg capture failed (exit 137): no error output
Recorded './memo.opus': 2.773s

If the source fails before any audio was captured, the command exits with code 1 and the error.

insert

Inserts new audio into an existing Ogg Opus file at --at. The existing audio is kept, and everything after the insertion point moves later. The file is edited in place (see How edits work). The new audio is encoded at the file's own channel count and sample rate of 48 kHz. --at may equal the file's duration, which appends the new audio.

$ pbtk audio insert --file ./memo.opus --at 1:05.5 --duration 3s
$ pbtk audio insert --file ./memo.opus --at 1.0 --from-wav ./aside.wav

Options

OptionRequiredDefaultDescription
--fileYes—Existing Ogg Opus file to edit in place
--atYes—Time in the file where the new audio is inserted, from 0 to the file's duration. Accepts a time (see Time format).
--durationNoUntil Enter or Ctrl+CLength to capture or to keep from a WAV. Without it, a live capture runs until Enter or Ctrl+C. With it, Ctrl+C aborts and the file is left untouched (see Stopping a capture).
--from-wavNo—Insert audio from this WAV file instead of capturing. Does not need ffmpeg.
--bitrateNo64000Opus bitrate for the new audio, from 6000 to 510000 bits per second

--capture-formatNoPlatform default (see Requirements)ffmpeg input format used for capture

Output

On success the command exits with code 0. It prints the length of the new audio, the snapped time where it was placed, the requested time, and the resulting duration. For the first example above, run on a 2:00 recording:

Inserted 3.000s at 65.494s (requested 65.500s) into './memo.opus': 123.020s

The file grew by 3.020 s, not 3.000 s: an insert adds the new audio's length plus the encoder's 6.5 ms lookahead, rounded up to whole 20 ms packets (see How edits work). The second example inserts a 1 s WAV at 1.0 s, which snaps to 0.994 s:

Inserted 1.000s at 0.994s (requested 1.000s) into './memo.opus': 124.040s

overwrite

Replaces audio in an existing Ogg Opus file, starting at --at, with new audio. The file's length stays the same unless the new audio runs past the end, in which case the file grows. Inside the file, the replaced span is the longest run of whole original packets, starting at the snapped time, that is no longer than the new audio (at least one packet), and the original audio resumes at or before the end of the new audio. The file is edited in place, and the same options as insert apply. --at may equal the file's duration, which appends.

$ pbtk audio overwrite --file ./memo.opus --at 12 --from-wav ./fix.wav

Options

OptionRequiredDefaultDescription
--fileYes—Existing Ogg Opus file to edit in place
--atYes—Time in the file where the replacement starts, from 0 to the file's duration. Accepts a time (see Time format).
--durationNoUntil Enter or Ctrl+CLength to capture or to keep from a WAV. Without it, a live capture runs until Enter or Ctrl+C. With it, Ctrl+C aborts and the file is left untouched (see Stopping a capture).

Output

On success the command exits with code 0 and prints the same kind of line as insert. For the example above, with a 0.5 s fix.wav and a 2:00 recording, the length stays the same:

Overwrote 0.500s at 11.994s (requested 12.000s) in './memo.opus': 120.000s

When the new audio reaches the end of the file, the file grows to fit it. Overwriting from 1:58 on a 2:00 recording with 5 s of audio, for example, gives a file 3.0 s longer:

Overwrote 5.000s at 117.994s (requested 118.000s) in './memo.opus': 123.000s

How edits work

insert and overwrite use packet splicing. The packets of the original file are copied unchanged, and only the new audio is encoded, by a fresh Opus encoder. The Ogg header and tags packets are kept byte for byte, and the granule positions are recalculated for the new packet sequence.

  • Snapping: the requested time snaps to the nearest packet boundary, usually every 20 ms. Ties go to the earlier boundary. The command prints the snapped time, so check it when precision matters. In a file made by pbtk audio record, packet boundaries sit 6.5 ms before each 20 ms mark (at 0.994 s, 1.014 s, 1.034 s and so on), because the file's pre-skip is 312 samples. A request for 1.0 s therefore snaps to 0.994 s, and the new audio, which starts 6.5 ms after the boundary, begins exactly on the 1.000 s mark.
  • Lookahead offset: the Opus encoder needs about 6.5 ms of lookahead. Mid-file, that lookahead cannot be trimmed, so the new audio starts about 6.5 ms after the snapped boundary. Edits at 0 are not affected, because the lookahead is absorbed by the file's pre-skip. When an edit lands at the very start of a file whose pre-skip is larger than the lookahead, the new audio is padded with silence so the decoder's pre-skip discards only that silence, and the whole new take is kept.
  • Insert length: insert adds ceil((N + 6.5 ms) / 20 ms) × 20 ms to the file, where N is the length of the new audio. A 1 s insert adds 51 packets, which is 1.020 s.
  • Overwrite inside the file: the replaced span is the longest run of whole original packets, starting at the snapped boundary, whose total length is at most N (the length of the new audio), and at least one packet. At the very start of a file whose pre-skip is larger than pbtk's (typical of other encoders), the replaced span is instead the shortest run of whole packets that covers the pre-skip plus the whole take, so the take stays audible; this can replace up to one packet (20 ms) of original audio past the requested end. Everywhere else the rule above applies. The first part of the new take, exactly as long as the replaced packets, is encoded into packets that fill them (20 ms frames first, then a shorter frame for any remainder), so the file keeps its length exactly, whatever the original packet size. Original audio resumes at or before the requested end. The rest of the new take is dropped, because it would otherwise overlap the original audio that resumes. With 20 ms packets, a 0.5 s overwrite replaces exactly 25 packets. For a file made with 60 ms packets, overwriting 0.5 s at 1.0 s replaces 8 packets (0.48 s) and keeps the length:
    Overwrote 0.500s at 1.014s (requested 1.000s) in './sixty.opus': 2.000s
  • Overwrite reaching the end: when the new audio reaches or passes the end of the file, all original packets from the snapped time on are replaced and the whole new take is kept, so the file grows. The resulting length is the snapped time + 6.5 ms + N exactly.
  • Joins: a short decoder transient is possible at each join. No crossfade or smoothing is applied.
  • In place and atomic: the edited file is written to a temporary file in the same directory, then renamed over the original. If an edit fails or is cancelled, the original file is unchanged and no temporary file is left behind.
  • Changed while recording: an edit notes the file's length and last-write time when it reads the file, and checks them again just before replacing it. If either changed, because something else wrote to the file during the capture, the edit fails and the other writer's file is kept:
    Error: File './edit.opus' changed while recording; no changes were written
  • Symlinks and permissions: if --file is a symbolic link, the file it points to is edited and the link stays a link. The edited file keeps the original's Unix file mode (on Windows, its attributes). For example, editing ./link.opus, a link to a file with mode 0600:
    Inserted 1.000s at 1.014s (requested 1.000s) into './link.opus': 3.020s
    leaves link.opus -> sixty.opus in place, and sixty.opus still has mode -rw-------.
  • Appending: insert or overwrite with --at equal to the file's duration adds the new audio at the end. The last original packet's padding, up to 20 ms of near silence that was trimmed from the end, becomes audible before the new audio.
  • Growing: overwrite grows the file when the new audio reaches the end. insert always grows the file.
  • Channels: edits keep the file's channel count, so the new audio is converted to match: a mono source is duplicated to stereo, and a stereo source is averaged to mono.

WAV input

--from-wav reads 16-bit PCM or 32-bit IEEE float WAV files, mono or stereo. Supported sample rates are 8, 12, 16, 24 and 48 kHz. Other rates are rejected, and the error suggests resampling first, for example ffmpeg -i in.wav -ar 48000 out.wav. Audio at rates below 48 kHz is upsampled to 48 kHz by linear interpolation.

Time format

--at accepts [[hh:]mm:]ss[.fff], a number of seconds such as 2.5, or a number with a suffix: ms, s or m, for example 500ms, 2s or 1.5m. --duration accepts the same forms. Negative values are rejected.

Packet lengths

Existing packets are copied whatever their frame size, from 2.5 to 120 ms. The 20 ms frame size applies to the new audio only.

Scope: the audio topic handles mono and stereo Ogg Opus files. Multichannel files, chained or multiplexed Ogg streams, and other formats are rejected with an error. A file whose header declares a channel count other than 1 or 2 is rejected with Unsupported Ogg Opus channel count 3; only mono and stereo files are supported.

Errors

Error exits: each action exits with code 1 and prints Error: <message> in these cases:
  • The file given to --file or --from-wav does not exist: File '<path>' not found.
  • --at is beyond the end of the file: Time <R>s is beyond the end of '<path>' (<D>s).
  • A live capture would need a keypress but no interactive console is available, for example over MCP or with redirected stdin: --duration or --from-wav is required when no interactive console is available.
  • ffmpeg is needed but not on PATH: ffmpeg was not found on PATH. Install ffmpeg (e.g. 'apt install ffmpeg' or 'brew install ffmpeg') or use --from-wav.
  • Windows capture without --device: --device is required on Windows, e.g. --device "audio=Microphone".
  • --channels is not 1 or 2, or --bitrate is outside 6000 to 510000.
  • No audio was captured: No audio was captured.
  • The file being edited was changed by something else during the capture: File '<path>' changed while recording; no changes were written.
  • The file's header declares a channel count other than 1 or 2: Unsupported Ogg Opus channel count <n>; only mono and stereo files are supported.
  • libopus is missing, the input is not a valid or supported Ogg Opus or WAV file, a time is malformed, or a capture fails. These print the specific message from the library or input check.

Cancelled

Cancelled exit: Ctrl+C during a capture that has --duration (or uses --from-wav) is not an error. Nothing is written, the command prints Cancelled; no changes were written and exits with code 130. See Stopping a capture.

MCP

The audio actions are available through pbtk mcp. A call that would capture live audio without --duration or --from-wav is refused with exit code 1, because it would wait for a keypress that an MCP call cannot send. Pass --duration or --from-wav for MCP calls. Cancelling or timing out such a call aborts it: nothing is written and the exit code is 130.
