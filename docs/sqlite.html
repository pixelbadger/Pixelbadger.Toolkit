tui Command Reference

tui

Opens an interactive terminal UI over an existing SQLite database file. The left panel shows a tree of the database's tables and views, which expands to show their columns. The right side has a multi-line query editor on top and a results pane below it. Press F5 or Ctrl+E to run the editor contents as one batch.

The UI runs on the alternate screen and needs an interactive terminal with at least 80×24 characters. It redraws to the current console size whenever the window is resized. Press Ctrl+Q or Ctrl+C to quit.

$ pbtk sqlite tui --db ./app.db

RegionContents
Tables (left, 32 columns wide)Tree with the database file name as root, then tables (names not starting with sqlite_) and views (suffixed (view)), each sorted by name. Expanding a node lists its columns as name TYPE with PK and NOT NULL markers.
Query (top right, about 40% of the height)Multi-line SQL editor. Long lines scroll horizontally to keep the cursor visible; lines are not wrapped.
Results (bottom right)A message line followed by a table of the last result set.
Status line (bottom row)Database file name, READ-ONLY when the file is not writable, transaction state (● UNSAVED CHANGES or saved), and key hints. Confirmation prompts replace this line.

Running SQL

Execute runs the whole editor text as one batch. Empty or whitespace-only text shows Nothing to execute. If a statement fails, the error is shown in red in the results pane and the whole batch has no effect.

The results pane shows the last statement that returns columns, with up to 1000 rows. The message line then reads N row(s) (T ms), or Showing first 1000 rows (more available) (T ms) when the cap applies. If no statement returns columns, the message line reports N row(s) affected (T ms) instead.

NULL values appear as dim NULL. BLOB values appear as <blob N bytes>. Other values are truncated to 40 characters with ….

Save and the write lock: the first batch that changes data opens a transaction and holds SQLite's write lock until you save or discard. While the lock is held, other processes that try to write get database is locked. Other processes can still read, and they see the data as it was before your changes. Ctrl+S commits the transaction, and F8 rolls it back. The status line shows ● UNSAVED CHANGES while there are changes waiting to be saved.
Transaction statements are refused: the TUI manages transactions itself. If a batch contains BEGIN, COMMIT, END, ROLLBACK, SAVEPOINT or RELEASE, the whole batch is refused without running and the message reads Transactions are managed by the TUI: Ctrl+S saves, F8 discards.

Saving, discarding and quitting

ActionResult
Ctrl+S with unsaved changesCommits the transaction, shows Changes saved and clears the unsaved state. If the commit fails (for example, the database is busy), the error is shown and the changes stay unsaved so you can retry.
Ctrl+S with no unsaved changesShows No changes to save.
F8 and yRolls back the transaction and shows Changes discarded.
F8 with no unsaved changesShows No changes to discard.
Ctrl+Q with no unsaved changesExits immediately.
Ctrl+Q with unsaved changesShows the prompt Unsaved changes: [S]ave, [D]iscard, [C]ancel. S commits and exits (if the commit fails, you stay in the TUI with the error shown). D rolls back and exits. C or Esc returns to the TUI.
Killing the process loses unsaved changes: if the process is terminated while there are unsaved changes, nothing from that transaction is persisted. SQLite rolls back the journal. Closing the session also rolls back any unsaved changes.

Options

OptionRequiredDefaultDescription
--dbYes—Path to an existing SQLite database file

Opening a database

The database is opened for reading and writing when the file is writable. If it is not writable, the database opens read-only: the status line shows READ-ONLY, and any mutating statement fails with the SQLite error in the results pane.

Error exits: the command exits with code 1, prints an error line and does not draw the TUI in these cases:
  • The file does not exist: Error: Database file '<path>' not found. The command never creates a file.
  • The file is not a SQLite database: Error: '<path>' is not a valid SQLite database: <sqlite message>
  • Input or output is redirected (no interactive terminal): Error: sqlite tui requires an interactive terminal
Not available over MCP: sqlite is an interactive command and is not exposed through pbtk mcp.
