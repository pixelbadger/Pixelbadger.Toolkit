Overview

The Paillier cryptosystem is a probabilistic, asymmetric encryption scheme with a remarkable property: arithmetic can be performed directly on encrypted data — no decryption required. The server performing the computation never sees the underlying values.

This implementation exposes a set of CLI commands under the crypto topic that let you generate keys, encrypt and decrypt integers and strings, and perform addition, subtraction, and scalar multiplication on ciphertext.

Property

How the Paillier Cryptosystem Works

Key Components

Paillier encryption uses four mathematical values. Two form the public key (safe to share) and three form the private key (must be kept secret).

Symbol Name Visibility Description
n Modulus Public Product of two large primes p × q. All arithmetic is performed mod n².
g Generator Public Fixed as n + 1 in this implementation (a common simplification).
λ Lambda Private lcm(p-1, q-1). Used as the decryption exponent.
μ Mu Private Modular inverse of λ mod n. Scales the result during decryption.

Encryption

To encrypt a plaintext integer m, a fresh random value r (coprime with n) is chosen. The ciphertext is:

c = g^m · r^n (mod n²)

Because r is random and discarded, encrypting the same m twice produces different ciphertexts — this is the probabilistic nature of the scheme.

Because g = n + 1, the term gm simplifies to 1 + m·n (mod n²).

Results of homomorphic operations are re-randomised as well: each output is multiplied by a fresh rⁿ (mod n²). No output ciphertext equals an input ciphertext, so a result cannot be linked to its inputs by comparing ciphertexts.

Decryption

Given the private key, the original plaintext is recovered in two steps. First, the L-function removes the randomness; then μ rescales the result:

L(x, n) = (x - 1) / n
m = L(c^λ mod n², n) · μ (mod n)

Homomorphic Addition

Multiplying two ciphertexts together in the encrypted domain produces the ciphertext of their plaintext sum:

Enc(m₁ + m₂) = Enc(m₁) · Enc(m₂) (mod n²)

Homomorphic Subtraction

Multiplication by the modular inverse of a ciphertext computes the difference:

Enc(m₁ - m₂) = Enc(m₁) · Enc(m₂)⁻¹ (mod n²)

Homomorphic Scalar Multiplication

Raising a ciphertext to an integer power multiplies the plaintext by that scalar:

Enc(m · k) = Enc(m)^k (mod n²)

Note: this is multiplication by a known plaintext scalar, not by another encrypted value. Fully encrypted multiplication requires a different (more expensive) scheme.

Limitation: Paillier is additively homomorphic only. Multiplying two encrypted values together is not supported in this scheme.

Key Generation

The generate-key command creates a fresh Paillier key pair and writes two JSON files: a public key (safe to distribute) and a private key (keep secret).

$ pbtk crypto generate-key --public-key-file public.json --private-key-file private.json
flowchart TD A([Start]) --> B[Generate large prime p\n~1024 bits] A --> C[Generate large prime q\n~1024 bits] B --> D{p ≠ q and\nn ≥ 2048 bits?} C --> D D -- No --> B D -- Yes --> E[n = p × q] E --> F[λ = lcm p−1, q−1] F --> G[μ = λ⁻¹ mod n] G --> H[Public key: n\nwrite to file] G --> I[Private key: n, λ, μ\nwrite owner-only file] H --> J([Done]) I --> J

Public key file (public.json)

Contains only N (the modulus). Safe to share freely.

{ "N": "2650...7391" }

Private key file (private.json)

Contains N, Lambda, and Mu. Written with owner-only Unix permissions (600) and must never be shared.

{ "N": "2650...7391", "Lambda": "1325...8432", "Mu": "9812...2049" }
Prime candidates are tested using the Miller-Rabin primality test with 20 witness rounds, giving a false-positive probability of less than 4⁻²⁰ ≈ 10⁻¹².

Numeric Operations

Encrypt a number

Takes a non-negative integer and a public key file. Writes the ciphertext to a JSON file.

$ pbtk crypto encrypt --number 42 --public-key-file public.json --out-file enc42.json
flowchart LR M[Plaintext\nm = 42] --> E PK[public.json\nn, g] --> E R([Random r\ncoprime with n]) --> E E[["c = gᵐ · rⁿ mod n²"]] --> OF[enc42.json\nciphertext, n]

Decrypt a number

Reads an encrypted number file and private key, writes the plaintext to stdout. If decryption fails (wrong key, malformed or out-of-range ciphertext, a ciphertext from a different key, or an invalid value), it prints Error: Decryption failed: input is invalid or was not encrypted with this key. and exits with code 1. A missing or unreadable file reports its own specific error.

$ pbtk crypto decrypt --in-file enc42.json --private-key-file private.json
flowchart LR EF[enc42.json\nciphertext c] --> D SK[private.json\nn, λ, μ] --> D D[["m = L(cλ mod n², n) · μ mod n"]] --> OUT([stdout: 42])

Homomorphic Operations on Encrypted Numbers

These commands operate entirely on ciphertext. No private key is needed and the plaintext values are never revealed to the process performing the computation.

Outputs are re-randomised: each one is multiplied by a fresh rⁿ (mod n²), so no output ciphertext equals an input ciphertext. multiply --scalar 0 yields a fresh Enc(0), and --scalar 1 yields a fresh re-encryption of the input. Both are indistinguishable from any other ciphertext.

add pbtk crypto add

Enc(a) · Enc(b) mod n² → Enc(a + b)

Multiplies the two ciphertexts together. Decrypting the result yields a + b.

pbtk crypto add --in-file1 enc_a.json --in-file2 enc_b.json --out-file enc_sum.json

subtract pbtk crypto subtract

Enc(a) · Enc(b)⁻¹ mod n² → Enc(a − b)

Multiplies the first ciphertext by the modular inverse of the second.

pbtk crypto subtract --in-file1 enc_a.json --in-file2 enc_b.json --out-file enc_diff.json

multiply pbtk crypto multiply

Enc(m)^k mod n² → Enc(m × k)

Raises the ciphertext to the power of a known plaintext scalar k.

pbtk crypto multiply --in-file enc_m.json --scalar 3 --out-file enc_product.json
flowchart TD A([Enc a]) --> ADD["add\nEnc(a) · Enc(b) mod n²"] B([Enc b]) --> ADD A --> SUB["subtract\nEnc(a) · Enc(b)⁻¹ mod n²"] B --> SUB A --> MUL["multiply\nEnc(a)^k mod n²"] K([Scalar k]) --> MUL ADD --> RA([Enc a+b]) SUB --> RS([Enc a−b]) MUL --> RM([Enc a×k])

String Operations

Strings are encrypted character-by-character: each Unicode code point is independently encrypted as an integer using the Paillier scheme. The result is a JSON array of encrypted numbers, one per character. This representation enables position-aware operations on the ciphertext without decryption.

Every encrypted string is padded to exactly 100 entries: the real characters followed by encrypted NUL (U+0000) padding. The padding is removed on decryption, so it is invisible in the plaintext.

An encrypted string file reveals nothing about the plaintext beyond the 100-character maximum: not its length, not which positions were edited, and not whether two files hold the same text. Whoever runs replace or substring knows the --start, --length and replacement they supplied, since those are plaintext inputs. Plaintext is read from files or stdin rather than command-line arguments so it does not appear in the process list or shell history.

encrypt-string

Encrypts a UTF-8 string as an array of encrypted Unicode code points. The plaintext is read from the file given by --string-file, or from stdin when the value is -. Exactly one trailing line ending (\n or \r\n) is stripped. The string may contain at most 100 Unicode characters, and the NUL character (U+0000) is rejected because it is reserved for padding. The output always contains exactly 100 encrypted entries. On success it prints Encrypted string written to '<path>'.

$ pbtk crypto encrypt-string --string-file hello.txt --public-key-file public.json --out-file enc_str.json
$ printf 'Hello' | pbtk crypto encrypt-string --string-file - --public-key-file public.json --out-file enc_str.json
flowchart LR S["Plaintext string\n\"Hello\""] --> RUNES["Enumerate\nUnicode runes\nH=72, e=101, l=108, l=108, o=111"] RUNES --> PAD["Pad with NUL\nto 100 entries\n95 × U+0000"] PAD --> ENC["Encrypt each\ncode point\nwith public key"] PK["public.json"] --> ENC ENC --> OUT["enc_str.json\n[EncryptedNumber × 100]\n5 real + 95 Enc(NUL)"]

decrypt-string

Decrypts all 100 entries and removes every NUL, so padding does not appear in the output. If decryption fails (wrong key, malformed or out-of-range ciphertext, a ciphertext from a different key, or an invalid character), it prints Error: Decryption failed: input is invalid or was not encrypted with this key. and exits with code 1. A missing or unreadable file reports its own specific error.

$ pbtk crypto decrypt-string --in-file enc_str.json --private-key-file private.json
flowchart LR EF["enc_str.json\n[EncryptedNumber × 100]"] --> DEC["Decrypt each\ncode point\nwith private key"] SK["private.json"] --> DEC DEC --> CHARS["Code points\n72, 101, 108, 108, 111, 0 × 95"] CHARS --> STRIP["Remove NUL padding\n(U+0000)"] STRIP --> STR(["stdout: \"Hello\""])

replace

Overwrites characters at a known position in an encrypted string without decrypting it. The replacement is read from the file given by --replacement-file, or from stdin when the value is -. Exactly one trailing line ending is stripped, and the NUL character is not allowed. The replacement is encrypted with the same public key (recovered from the ciphertext metadata) and substituted into the array at the specified index.

The range is checked against the encrypted array length (100 for padded strings), so writing past the real end writes into the padding and succeeds. For example, replacing at --start 7 with X in an encrypted hello decrypts to helloX. Every position in the output gets a fresh ciphertext: replaced positions are newly encrypted and all others are re-randomised, so the output cannot be linked to the input by comparing ciphertexts. Replace rejects an empty encrypted string.

$ pbtk crypto replace --in-file enc_str.json --start 0 --replacement-file j.txt --out-file enc_str2.json
flowchart LR EF["enc_str.json\n[EncryptedNumber × 100]"] --> RERAND["Re-randomise each\nuntouched entry\n(× fresh rⁿ mod n²)"] REP["j.txt\n\"J\" at index 0"] --> RUNES2["Enumerate runes\nJ=74"] RUNES2 --> REENC["Encrypt replacement\nwith public key\n(from ciphertext N)"] RERAND --> SPLICE["Splice at start index\n(past the real end writes into padding)"] REENC --> SPLICE SPLICE --> OUT["enc_str2.json\n[EncryptedNumber × 100]\nevery entry fresh"]

substring

Slices an encrypted string by position, returning a new encrypted array of the selected range. Each entry in the slice is re-randomised, and the result is padded with fresh encrypted NUL back to 100 entries. Omitting --length takes the slice to the end of the array, including padding. No private key is needed. On success it prints Encrypted substring written to '<path>'. Substring rejects an empty encrypted string.

$ pbtk crypto substring --in-file enc_str.json --start 1 --length 3 --out-file enc_sub.json
flowchart LR EF["enc_str.json\n[EncryptedNumber × 100]"] --> SLICE["Slice [start .. start+length)\ne.g. [1..4)"] SLICE --> RR["Re-randomise\neach entry"] RR --> PAD2["Pad with fresh Enc(NUL)\nto 100 entries"] PAD2 --> OUT["enc_sub.json\n[EncryptedNumber × 100]\n3 real + 97 Enc(NUL)"]

Constraints and Limits

ConstraintValueReason
Minimum key size 2048 bits NIST minimum recommendation for asymmetric security
Plaintext range (numbers) 0 ≤ m < n Paillier requires the message to be smaller than the modulus
Plaintext integers Non-negative only Paillier works in Z/nZ; negative values are not natively supported
Max string length 100 Unicode characters; always padded to 100 entries (each file ≈ 190 KB) Each character requires one full ciphertext; the fixed 100-entry size limits file size and hides the true length
NUL character Not allowed (U+0000) in plaintext or replacement Reserved for padding; decryption removes every NUL
String character set Full Unicode code points, except U+0000 Characters are stored as Unicode scalar values, supporting any language
Scalar multiplier Non-negative integer Negative scalars not supported; multiply by 0 produces a fresh Enc(0), and multiply by 1 a fresh re-encryption
Input validation All characters share one public key N (≥ 2048 bits); each ciphertext satisfies 0 < c < n² and is coprime to n; at most 100 entries Malformed or mismatched inputs are rejected before any computation. replace and substring reject an empty encrypted string
Decryption errors Error: Decryption failed: input is invalid or was not encrypted with this key. (exit 1) Applies to wrong key, malformed or out-of-range ciphertext, a ciphertext from a different key, and invalid characters. Missing or unreadable files keep their specific error
IntegrityNot providedPaillier ciphertexts are malleable: a well-formed ciphertext that has been modified decrypts to a different value without an error. Use a separate signature or MAC if you need tamper detection
Compatibility Unpadded files written by previous versions still decrypt replace and substring on those files produce padded 100-entry output
