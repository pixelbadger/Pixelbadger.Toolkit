RAG rag

Lucene text search over chunked plain-text documents — ingest, list, get, search and delete

The rag topic stores plain-text files in a local Lucene.NET index. Each file is recorded as a header document with a stable 32-character ID, and its text is split into chunks that are indexed for full-text search. Use ingest to add or replace a file, list and get to read the index back, search to run Lucene queries over the chunks, and delete to remove a document and its chunks.

Only plain text is supported (UTF-8, optionally with a byte-order mark). PDF, HTML and Word files are not supported. Each ingest call takes exactly one --file; directories and glob patterns are not accepted.

ingest

Reads a plain-text file, splits it into chunks, and writes a header document and its chunks to the index in a single commit. Without --id, ingest always creates a new document with a new ID, even if the same file has been ingested before. On success, the ID is printed.

With --id set to an existing document ID, ingest updates that document: all of its old chunks are removed and replaced with the new content. The ID and created_utc are kept, updated_utc is set to the current time, and the title, path, hash and chunks are replaced. If the update fails before the commit, the old version stays intact. An unknown --id is an error.

$ pbtk rag ingest --file ./notes.txt
$ pbtk rag ingest --file ./notes-v2.txt --id 3f2a9c1e5b7d4e8fa0b1c2d3e4f5a6b7 --title "Meeting notes"
$ pbtk rag ingest --file ./book.txt --index library --chunk-size 1500 --chunk-overlap 200

list

Lists header documents, sorted by createdUtc ascending and then by ID. The output reports the total number of documents, the page, the page size and the total number of pages. A page past the end returns no documents and still exits with 0. A missing index is listed as empty.

$ pbtk rag list --page 2 --page-size 20

search

Runs a Lucene query over the chunks of all documents. Results contain chunks only, scored with BM25 and ordered by score, highest first. The default field is content, and the query syntax is the classic Lucene syntax, described in Lucene query syntax. A query that cannot be parsed exits with an error reading Invalid query: ….

$ pbtk rag search --query '"quick brown" AND fox~' --page-size 5
$ pbtk rag search --query "title:notes AND budget" --index-path ./my-index --format json

delete

Removes a document's header and all of its chunks in one commit. An unknown ID is an error and leaves the index unchanged. Deleted space is reclaimed when Lucene merges segments.

Index location

By default, an index named default is stored in ~/.pbtk/rag/default. --index <name> selects ~/.pbtk/rag/<name>. Names must start with a letter or digit, may contain letters, digits, dots, underscores and hyphens, and are at most 64 characters long. An invalid name is an error.

--index-path <dir> stores the index in the given directory instead, and wins over --index when both are given.

ingest and delete create the index directory if needed. Read actions (list, get and search) never create it. On a missing or empty index, list and search return no results, and get reports that the document was not found.

The index is a Lucene 4.8 index. Only one writer can change an index at a time. Readers never wait for writers. Index locks are local to one machine, so an index on a network filesystem shared between machines is not coordinated.

Output formats

--format text (the default) prints human-readable output. Its layout is not a stable format, so use --format json when a program reads the output. Each JSON call prints one object with camelCase field names. Errors are always plain text on stderr with exit code 1, whatever --format is.

ingest

{"id":"...","action":"created","title":"...","sourcePath":"...","chunkCount":0,"charCount":0}

action is created or updated.

Timestamps use ISO-8601 round-trip format. sha256 is the hash of the file bytes. start and end are character offsets into the normalized text of the document, as described in Chunking.

Chunking

Before chunking, ingest normalizes the text: line endings become \n, runs of blank lines collapse into a single blank line, and leading and trailing whitespace is removed. Paragraphs are separated by blank lines.

  • Whole paragraphs are packed greedily into chunks of at most --chunk-size characters.
  • A paragraph longer than --chunk-size is split at sentence ends first, then at spaces. A single word longer than the chunk size is split at the character limit.
  • With --chunk-overlap above 0, each chunk after the first starts with up to that many characters of the preceding text, beginning at a word boundary. The overlap counts toward the chunk size, so no chunk, overlap included, is longer than --chunk-size.

Without overlap, the chunks cover all of the document's non-whitespace text exactly once and in order. Each chunk's start and end give its position in the normalized text.

File limits: the file must exist and be 50 MB or smaller. It is decoded as UTF-8, and a byte-order mark is honoured. A file containing a NUL character is rejected as not a plain text file, and a file with no non-whitespace text is rejected as containing no text. All of these are errors that leave the index unchanged.

Lucene query syntax

search uses the classic Lucene query parser. Bare terms search the content field. The following fields are available:

  • content: the text of a chunk (default field)
  • title: the document title, matched word by word
  • doc_id: the document ID, matched exactly
  • kind: header or chunk. search always adds kind:chunk, so header documents never appear in results

TermbudgetChunks containing the word budget
Phrase"quick brown"Chunks containing the words in that order

Titletitle:wordChunks of documents whose title contains word
Wildcardqui*Terms starting with qui. A wildcard cannot be the first character.
Fuzzyfox~Terms close to fox in spelling
$ pbtk rag search --query "fox AND NOT dog"

MCP tools

All five actions are exposed as MCP tools: rag_ingest, rag_list, rag_get, rag_search and rag_delete. Their options match the command line. See mcp for how to serve and save profiles.
