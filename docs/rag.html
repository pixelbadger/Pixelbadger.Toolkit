RAG rag

Lucene text search over chunked plain-text documents — ingest, list, get, search and delete

The rag topic stores plain-text files in a local Lucene.NET index. Each file is recorded as a header document with a stable 32-character ID, and its text is split into chunks that are indexed for full-text search. Use ingest to add or replace a file, list and get to read the index back, search to find chunks by plain-text terms, and delete to remove a document and its chunks.

Only plain text is supported (UTF-8, optionally with a byte-order mark). PDF, HTML and Word files are not supported. Each ingest call takes exactly one --file; directories and glob patterns are not accepted.

ingest

Reads a plain-text file, splits it into chunks, and writes a header document and its chunks to the index in a single commit. Without --id, ingest always creates a new document with a new ID, even if the same file has been ingested before. On success, the ID is printed.

With --id set to an existing document ID, ingest updates that document: all of its old chunks are removed and replaced with the new content. The ID and created_utc are kept, updated_utc is set to the current time, and the path, hash and chunks are replaced. The title is kept unless --title is given. If the update fails before the commit, the old version stays intact. An unknown --id is an error.

$ pbtk rag ingest --file ./notes.txt
$ pbtk rag ingest --file ./notes-v2.txt --id 3f2a9c1e5b7d4e8fa0b1c2d3e4f5a6b7 --title "Meeting notes"
$ pbtk rag ingest --file ./book.txt --index library --chunk-size 1500 --chunk-overlap 200

list

Lists header documents, sorted by createdUtc ascending and then by ID. The output reports the total number of documents, the page, the page size and the total number of pages. A page past the end returns no documents and still exits with 0. A missing index is listed as empty.

get

Shows one document: its header fields followed by its chunks, ordered by chunk index. By default all chunks are returned; --from-chunk and --to-chunk select an inclusive, 0-based range, which is read from the index without loading the other chunks. The header, including chunkCount, is always returned. A --to-chunk beyond the last chunk is clamped to it; a --from-chunk beyond the last chunk returns the header with an empty chunk list. An unknown ID is an error, as is a negative bound or a --from-chunk greater than --to-chunk.

$ pbtk rag get --id 3f2a9c1e5b7d4e8fa0b1c2d3e4f5a6b7 --format json
$ pbtk rag get --id 3f2a9c1e5b7d4e8fa0b1c2d3e4f5a6b7 --from-chunk 3 --to-chunk 5

search

Searches the chunks of all documents for plain-text terms. The query is ordinary text: no character is query syntax, so nothing can fail to parse. It is analysed like the indexed text (see Search behaviour), and a chunk matches when it contains any of the resulting terms in its text or its document's title. Results contain chunks only, ranked by BM25, highest score first. Each result also carries its position in the document (chunk 4/7 in text output) and the document's size. A query with no searchable terms (empty, only punctuation, or only stop words) exits 1 with Query has no searchable terms., and one with more than 200 distinct terms exits 1 with Query has too many terms (max 200).

$ pbtk rag search --query "what's the default for --port?" --page-size 5
$ pbtk rag search --query "meeting budget" --index-path ./my-index --format json

delete

Removes a document's header and all of its chunks in one commit. An unknown ID is an error and leaves the index unchanged. Deleted space is reclaimed when Lucene merges segments.

Index location

By default, an index named default is stored in ~/.pbtk/rag/default. --index <name> selects ~/.pbtk/rag/<name>. Names must start with a letter or digit, may contain letters, digits, dots, underscores and hyphens, and are at most 64 characters long. An invalid name is an error.

--index-path <dir> stores the index in the given directory instead, and wins over --index when both are given. An empty or unresolvable path is an error (Invalid index path '<path>'.). If no --index-path is given and the home directory cannot be determined, the command fails with Cannot determine the home directory; use --index-path.

ingest and delete create the index directory if needed. Read actions (list, get and search) never create it. On a missing or empty index, list and search return no results, and get reports that the document was not found.

The index is a Lucene 4.8 index. Only one writer can change an index at a time. Readers never wait for writers. Index locks are local to one machine, so an index on a network filesystem shared between machines is not coordinated.

Output formats

--format text (the default) prints human-readable output. Its layout is not a stable format, so use --format json when a program reads the output. Each JSON call prints one object with camelCase field names. Errors are always plain text on stderr with exit code 1, whatever --format is.

{"id":"...","action":"created","title":"...","sourcePath":"...","chunkCount":0,"charCount":0}

action is created or updated.

fromChunk and toChunk are the range actually returned, after clamping; both are null when no chunks are returned.

 "results":[{"id":"...","title":"...","chunkIndex":0,"chunkCount":0,"score":0.0,"start":0,"end":0,"charCount":0,"content":"..."}]}

{"id":"...","deleted":true}

Timestamps use ISO-8601 round-trip format. sha256 is the hash of the file bytes. In search results, chunkCount and charCount describe the owning document. start and end are character offsets into the normalized text of the document, as described in Chunking.

Chunking

Before chunking, ingest normalizes the text: line endings become \n, runs of blank lines collapse into a single blank line, and leading and trailing whitespace is removed. Paragraphs are separated by blank lines.

  • Whole paragraphs are packed greedily into chunks of at most --chunk-size characters.
  • A paragraph longer than --chunk-size is split at sentence ends first, then at spaces. A single word longer than the space left for text (--chunk-size minus --chunk-overlap) is split at that limit.
  • With --chunk-overlap above 0, each chunk after the first starts with up to that many characters of the preceding text, beginning at a word boundary. The overlap counts toward the chunk size, so no chunk, overlap included, is longer than --chunk-size.

Without overlap, the chunks cover all of the document's non-whitespace text exactly once and in order. Each chunk's start and end give its position in the normalized text.

File limits: the file must exist and be 50 MB or smaller. It is decoded as UTF-8, and a byte-order mark is honoured. A file containing a NUL character is rejected as not a plain text file, and a file with no non-whitespace text is rejected as containing no text. All of these are errors that leave the index unchanged.

Search behaviour

Chunk text and document titles are analysed identically when indexed and when searched: the text is split into words, possessives (badger's) lose the 's, words are lower-cased, stop words are dropped, and the rest are reduced to their English stem with the Porter stemmer. So numbers matches number and line-number, and steganography? finds the same chunks as steganography.

  • Any term matches. Each distinct term is optional; chunks matching more terms, and rarer terms, score higher under BM25 (k1 1.2, b 0.75).
  • Title matches count. A term found only in a document's title matches every chunk of that document.
  • Chunks only. Header documents are never returned.
  • Negations are kept. no, nor and not are searchable words.

The stop words are the NLTK English list without the negations no, nor and not:

MCP tools

All five actions are exposed as MCP tools: rag_ingest, rag_list, rag_get, rag_search and rag_delete. Their options match the command line. See mcp for how to serve and save profiles.
